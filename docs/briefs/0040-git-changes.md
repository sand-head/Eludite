## Goal

The Git Changes window (View > Git Changes, Ctrl+0, Ctrl+G) is Visual Studio's: the branch name with the incoming and outgoing counts, a commit message box with Commit All, Commit All and Push, Amend, the Staged Changes and Changes groups with per-file Stage, Unstage, Discard (Undo Changes, confirmed), the stash list, and a link to the Git Repository window (the log with its graph, branches, tags, stashes, Checkout, New Branch, Merge, Rebase, Cherry-pick, Reset, Delete). Files in the Workspace window and the document tabs carry Visual Studio's status glyphs and colors (added, modified, untracked, ignored, conflicted); the status bar shows the branch, the pending count and the incoming and outgoing arrows with Fetch, Pull, Push and Sync as in Visual Studio's bottom-right. Compare with Unmodified (the file's context menu and `eludite.git.diff`) opens a two-pane diff document with the gutter marks of brief 0016's diff; the editor's gutter shows the working tree's changed lines against the index. Every action is a command with a schema (`eludite.git.*`), so an agent reads the status, stages, commits, creates a branch and inspects the log through the same bus; agents never push or alter history without the `execute` class and the policy's `git` object. Everything runs through libgit2 off the UI thread with a generation number; a `git` executable is used for nothing.

## Contract

- **Status.** `eludite.git.status` (read) answers within 50 ms p95 on a 10,000-file repository with 100 changes from the cached status (recomputed by the watcher off the UI thread; `generation` identifies it); the window, the Workspace glyphs, the tabs and the status bar render from the same status; a repository-less folder shows "Create Git Repository" (Visual Studio's) and `eludite.git.init`.
- **Commit.** `commit` with `all` stages everything first (Commit All); the identity comes from the repository config, the global config, then `git.userName` and `git.userEmail`, else the refusal; `amend` is `history` class for agents; the message box keeps a draft per repository across restarts (brief 0021's state).
- **Branches and sync.** `checkout` of a branch refuses a dirty tree unless `force` (never for agents) or the tree is clean for the switch (libgit2's safe checkout); `fetch`, `pull`, `push` run off-thread with progress in the status bar and a Cancel; a credential failure says which helper or agent was tried; `git.autoFetchMinutes` 0 by default (no network unless asked, PLAN.md section 2); `push` is `execute` with `git.push` `prompt` by default for agents; `force` refused for agents outright.
- **History.** `merge`, `rebase`, `cherry-pick` stop at the first conflict with the conflicted paths; the files open with markers and the gutter shows the sides; staging a conflicted file resolves it; `rebase` continues with `git-rebase` `continue` or `abort`. `reset` `hard` and `discard` are `dangerous` with a confirmation in the UI.
- **Diff.** `diff` returns at most 2,000 changed lines of context with the hunks (the rest counted); Compare with Unmodified scrolls the two panes together and jumps between hunks with F8 and Shift+F8 as Visual Studio's diff viewer does; the editor's gutter marks follow the index within 200 ms of an edit on idle.
- **Stashes and worktrees.** `stash push` with a message and `include_untracked`; `pop` on a conflict behaves as merge; worktrees are listed with their branch and path, added under `<repo>/.worktrees/<name>` by default (Eludite's own convention from `docs/briefs/README.md`) or a given path, removed only when clean unless `force` (not for agents).
- The UI thread never waits on libgit2; every call carries the generation and stale answers are dropped (invariant 12); no `git` process is started by this brief; nothing runs at startup beyond discovering the repository and reading the cached status once the workspace opens.
- Commit messages: one plain, direct, active-voice line each; no body, no trailers.

## Proving test

- `crates/git`: every operation against temporary repositories, including a bare remote for fetch, pull, push and ahead/behind; the conflict and the resolution; stash and worktree cases; blame; the graph lanes; the identity refusal; the watcher bumps the generation on an index write; cancellation of a long log.
- `crates/commands`: the schemas parse and the permission classes and the `git` policy object apply.
- `crates/eludite` headless tests: the window lists the groups from a temporary repository, Stage moves a file between groups, Commit All commits with the message and clears the box, Amend, Discard asks and then restores the file, the status bar shows the branch and counts, the Workspace glyphs and the tab glyph change with the file, Compare with Unmodified opens the two panes with the right hunks and F8 moves, the editor's gutter marks appear after an edit and clear after a stage, Checkout of a dirty tree is refused with the message, New Branch creates and switches, a merge conflict opens the file with markers and staging resolves it, Fetch against the bare remote updates the incoming count, Push with `prompt` asks for an agent and runs for the user, a stale status (older generation) is not rendered, an agent's `status` answer matches the window, the no-repository state shows Create Git Repository and `init` creates one, the draft message survives a reopen.
- The Xvfb run's screenshots in the report.

## Budget

- `status` 50 ms p95 from the cache on a 10,000-file, 100-change temporary repository; the first status of such a repository under 500 ms off-thread.
- The window renders 1,000 changed files with no frame over 8 ms (virtualized list, measured with `assert_budget`).
- Compare with Unmodified on a 5,000-line file opens in under 100 ms.
- No new dependency (git2 and notify are in the build).
