## Goal

Edit > Find and Replace > Find in Files (Ctrl+Shift+F) opens Visual Studio's dialog: the search text, Match case, Match whole word, Use regular expressions, Look in (Entire Solution, Current Project, Current Document, All Open Documents, a folder), File types (`*.cs;*.cshtml`), Append results and Keep modified files open, with results in the Find Results 1 or 2 tool window grouped by file with the line, the match highlighted, the count and the elapsed time, F8 and Shift+F8 stepping through them into the editor. Replace in Files (Ctrl+Shift+H) adds the replacement with regex groups, Replace Next, Replace All and Skip File; Replace All applies through the workspace-edit applier as pending changes with brief 0016's review view, so every replacement is previewed, accepted or rejected per file, and is one undo step per document. The search runs at ripgrep speed off the UI thread, streams results as they come, is cancelable, honors `.gitignore` and the solution's excluded folders, and reads open documents' unsaved text instead of the disk. Agents use `eludite.search.find` and `eludite.search.replace` with the same arguments and a capped, paged answer.

## Contract

- **Speed and streaming.** The first result renders within 50 ms of Enter on this repository; a literal search over 50,000 files (the synthetic tree, 500 MB) completes within 1.5 times `rg`'s time on the same machine (measured in the crate's benchmark, reported); results stream in file order, the window stays at 60 Hz while they arrive (batched per frame), Stop cancels within 50 ms.
- **What is searched.** Files under the scope not excluded by `search.excludes`, `.gitignore` when `search.useGitignore` is on, the solution's excluded folders, `search.maxFileSize`; binary files skipped (ripgrep's NUL rule); open documents searched from their buffers (unsaved text) and reported under their paths; a document's dirty text counts once.
- **Matching.** Visual Studio's semantics: Match case, Match whole word, regular expressions (Rust regex syntax, which is .NET-compatible for the common forms; the dialog's help link names the differences), multiline off; the query history; `include` and `exclude` as Visual Studio's File types (`;` separated globs, `!` prefix excludes).
- **Replace.** Replace Next replaces the match under the editor caret and moves; Replace All collects the edits and, with preview (the default), opens them as pending changes in brief 0016's review view grouped by file (Accept, Reject, Accept All; one undo step per document; unopened files are opened only when accepted unless Keep modified files open is off, then written directly after acceptance); `preview: false` from an agent is `execute` and applies at once; a file changed on disk since the search is skipped with a row in the results and never overwritten blindly (the edits are checked against the searched text).
- **Results windows.** Two, as Visual Studio's; Append adds under a separator; the count line; F8 and Shift+F8 step and open the editor with the match selected; Clear; the window follows the active results of the last search; an agent's `find` with `results_window` shows there too, else it is answered only.
- The UI thread never waits on the walker or the matcher; every search carries a generation and a canceled or superseded search's results are dropped (invariant 12); no network.
- Commit messages: one plain, direct, active-voice line each; no body, no trailers.
