## Goal

Right-click a project or the solution and choose Manage NuGet Packages (Visual Studio's name) to open the window with its four tabs: Browse (search across the configured sources with prerelease and the version list), Installed (per project or the whole solution, with the version, the requested range and the source), Updates (with Select All and Update), and Consolidate (projects on different versions of one package, with the version to settle on). Install, update, uninstall and consolidate edit the project files (or `Directory.Packages.props` under Central Package Management) through the host, preserving formatting, then restore; the Output window's "Package Manager" source shows what NuGet did, and the Error List shows restore errors with click-through. The Workspace window gains the Dependencies node with Packages (and their transitive packages on expand), Projects and Frameworks under each project, as Visual Studio shows them, with a yellow warning glyph on a package that has a known vulnerability or is deprecated. Sources come from `NuGet.config` hierarchy (machine, user, solution), with the Package Sources page in Options; private feeds authenticate through the installed credential providers (the NuGet plugin protocol; the Azure Artifacts provider is the common one) or a prompt in the shell, and the credential is kept for the session. Lock files (`packages.lock.json`) are respected on restore and updated on change. Agents use `eludite.nuget.*` with the same arguments: `search`, `installed`, `updates`, `install`, `uninstall`, `update`, `consolidate`, `sources`, `restore`, under the policy's `nuget` object (reads allowed; changes `prompt` by default; adding a source `prompt`).

## Contract

- **Sources.** The `NuGet.config` chain as NuGet reads it; the Options page edits the user file; a source that fails answers an error row in the window and the others' results still show; nothing contacts a source at startup, only when the window opens, a tab asks, or an agent calls; search results and metadata are cached per source for the session.
- **Changes.** `install`, `update`, `uninstall` and `consolidate` edit the project file(s) or `Directory.Packages.props` (CPM detected from `ManagePackageVersionsCentrally`), preserving formatting, element order and comments; then restore unless `nuget.restoreOnChange` is off; the answer names the edited files, the resolved version and the restore result; a failed restore leaves the edit in place with the Error List rows, as Visual Studio does; the solution generation advances; the tree updates.
- **Updates and Consolidate.** Updates lists each installed package whose latest matching version (prerelease per the check box) is newer, per project; Consolidate lists packages installed at different versions across projects with the highest as the default target.
- **Vulnerabilities.** A package with a known vulnerability (from the source's registration data) or a deprecation shows the yellow glyph in the tree, a badge in Installed and Updates, and a line in the detail pane with the severity and advisory link; agents see `vulnerabilities` in `installed`.
- **Lock files.** With `nuget.lockFiles: respect`, restore uses `--locked-mode` when a lock file exists and a change updates it; `ignore` restores without it.
- **Credentials.** Credential providers discovered as NuGet does (the plugin folders and `NUGET_PLUGIN_PATHS`), then the shell's prompt (refused for agents with `credentials_required`), kept for the session, never written by Eludite.
- **Policy and audit.** Reads are `read`; changes are `execute` under `nuget.change` (`prompt` by default for agents); source changes under `nuget.sources`; every change is audited with the project, package and version.
- The UI thread never waits on the host or the network; every call carries the generation and a cancellation; the host's stdout stays protocol-only (NuGet's own logging goes to the host's log and the Output stream).
- Commit messages: one plain, direct, active-voice line each; no body, no trailers.

## Budget

- A search on the local feed answers in under 200 ms; the Installed tab of a 20-project solution in under 300 ms from the assets files; an install plus restore of a small package in under 5 s warm.
- The window with 500 search results keeps frame p99 under 8 ms (virtualized; `assert_budget`); icons never block.
- Dependencies: the NuGet.Client packages (Apache-2.0) in the host, versions pinned in `Directory.Packages.props`; no new Rust crate.

## Exit criterion

1. `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` green; `dotnet build` zero warnings and `dotnet test` green with the NuGet tests running against the local feed.
2. The report records the budget numbers, the sources and credential behavior, the CPM and lock-file rules as shipped, and what the web package UI (npm, pnpm, yarn, bun; PLAN.md section 7) can reuse from the window.
3. `CLAUDE.md`, `README.md` if touched, `corpus/README.md` and the briefs index match the repository.
