## Goal

A breakpoint in TypeScript and one in C# are the same experience: F5 on an ASP.NET Core project with a `wwwroot` or a Vite front-end starts Kestrel under netcoredbg (or Mono), opens the page in the Web Browser window (brief 0037), then attaches vscode-js-debug to that tab, so the Call Stack shows both processes, a breakpoint in `app.ts` stops the page at the mapped source line, Locals show the page's variables, and every `eludite.debug.*` command works on the browser session by `session`. Debug > Attach to Process... lists the browser tabs beside the processes, and `eludite.debug.attach` takes a `tab`. The agent's `eludite.browser.*` calls and its `eludite.debug.*` calls name the same tab, so "set a breakpoint in the click handler, click the button, read the locals" is three commands. vscode-js-debug (MIT) is located at run time like netcoredbg: fetched by `tools/js-debug/fetch.sh` from its pinned GitHub release by checksum, run with the Node found on the machine, never vendored.

## Contract

- **Attach.** `attach` with `tab` attaches vscode-js-debug to that Web Browser tab (embedded or external engine) through the engine's remote debugging port on loopback; with `url` to an external Chrome started with a remote debugging port; `adapter: javascript` with `pid` is refused with the message that a browser is attached by tab or url. The session is `attached`, named after the tab's title (updated when the title changes), Stop detaches and leaves the page running, the tab closing ends the session with `design` and a message. The permission class follows the attach rule: `execute` for a tab Eludite opened, `dangerous` otherwise.
- **Child sessions.** js-debug's `startDebugging` reverse request creates a child session with `parent`, listed under its parent in `sessions` and the Call Stack's selector; commands on the parent address the parent only; Stop on the parent ends its children; the compound's first break across parent and children answers the agent as brief 0028's compound does.
- **Compound.** `start` on a web project with `browser: built_in` (brief 0037) and `debugger.attachBrowser` on attaches js-debug to the opened tab once the page is up, as one compound: the summary names both sessions; `compound` with an explicit `browser` entry does the same for any server entry. The attach never delays the server's session; a failed attach (no Node, no js-debug) leaves the server's session running and says so in the summary's `message` and in the Output window, with `tools/js-debug/fetch.sh` named when js-debug is missing and the Node requirement when Node is.
- **Breakpoints by language.** Every breakpoint still goes to every adapter whose file kinds include the file; others leave no row under `breakpoints[].sessions`; a file kind nobody claims goes to every adapter as today. The Breakpoints window shows the original path for a mapped breakpoint and binds through js-debug's `setBreakpoints` on it; `breakpoints_failed` (brief 0036) covers js-debug's `verified: false` with its message.
- **Exceptions.** The shell's exception plan maps to js-debug's `all` and `uncaught`; `exception_info` works; the Exception Settings window shows the JavaScript group when a browser session is live.
- **Source maps.** Frames carry `source.original` (the mapped path when js-debug gives one) and `source.generated`; the execution point opens the original; `evaluate`, `snapshot`, `variables`, `set_variable`, `run_until`, `trace` and tracepoints (js-debug supports `logMessage`) work on the browser session; `wait` and `interrupted_by` as for the others.
- **Discovery.** js-debug and Node are located, never bundled; the version of each is in `state.sessions[].adapter_version`; nothing of them loads at startup.
- The UI thread never waits on the adapter or Node; the engine's remote debugging port binds loopback only and is reported, never guessed; no new dependency in the shell.
- Commit messages: one plain, direct, active-voice line each; no body, no trailers.

## Budget

- Attach to the tab after the page is up: under 1.5 s to `running` with js-debug (measured in the real test when it runs); the fake attach adds under 50 ms to brief 0037's launch.
- A browser session's `snapshot` under 50 ms p95 (fake); frame p99 unchanged with two sessions (brief 0028's assertion with `assert_budget`).
- No new dependency in the shell; vscode-js-debug (MIT) and Node are located tools.
