## Goal

Test > Test Explorer (Ctrl+E, T) opens Visual Studio's Test Explorer: the hierarchy (project, namespace, class, test; Cargo package, module, test for Rust), a filter box, Run All, Run, Debug, Run Failed, Repeat Last Run, live results with durations, per-test output and failure messages with stack traces, failures as Error List rows with click-through, and the same through `eludite.test.*` commands for agents (`discover`, `run`, `debug`, `results`, `cancel`). .NET tests are discovered and run out of process by `eludite-host` through Microsoft.Testing.Platform's server mode (JSON-RPC between the host and the test application, preferred) and, for projects that have not migrated, the VSTest translation-layer protocol to `vstest.console`; Rust tests through `cargo test -- --list` and `cargo test` with libtest's output parsed by the shell's Cargo path. Debug Test starts the test host under the right adapter (netcoredbg for .NET, `eludite-dbg-mono` for .NET Framework off Windows, lldb-dap with `test: true` for Rust) as a session of brief 0028 and stops at the test's first line. The Test Explorer is the surface PLAN.md's Phase 1 exit names and the one proposal 0001's proving scenario will call next.

## Contract

- **Discovery.** `eludite.test.discover` (read): `project?`, `rebuild?` (default: build first through `eludite.build.project` for .NET and `cargo test --no-run` for Rust when the output is stale, as F5 does). The host discovers every test project of the solution (or the one named) with its protocol (`TestProjectInspector`), runs discovery in the test application (MTP) or `vstest.console` (VSTest), and streams `eludite/test/update` notifications (`discovered` items with id, display name, fully qualified name, source, line, traits, project, protocol) until `discoveryComplete`. The shell builds the tree (project > namespace > class > test for .NET; package > module path > test for Rust) and answers with counts; agents get the tree pages (`max_items` default 500, cursor). Discovery is cached per solution generation and per build; a build invalidates it.
- **Running.** `eludite.test.run` (execute): `ids?` or `filter?` (a substring of the fully qualified name, or a trait `name=value`), `project?`, `failed_only?`, `wait_ms` (default 0 from the UI, 30,000 from an agent; max 300,000). Runs through MTP (`testing/runTests` with the ids) or VSTest (`TestExecution.RunAllWithDefaultHost` with the test cases) or cargo (`cargo test -p <pkg> -- --exact <names>`, one process per package); results stream (`running`, `passed`, `failed`, `skipped` with duration, message, stack trace, output) into the window live, the Error List gets a row per failure (source and line from the stack trace's first frame in the project), the status bar reads `Tests: 12 passed, 1 failed, 2 skipped (3.2 s)`, and the Output window gets a `Tests` source with the runners' output. The answer carries the run id and, after the wait, the summary with the failed tests' messages (cut at 2,000 characters each, `truncated`). Run All runs every project; Run Failed the last run's failures; Repeat Last Run the last set.
- **Cancel.** `eludite.test.cancel` (execute): `run?`; MTP `testing/cancel` or VSTest `TestExecution.Cancel`, cargo's process group killed; the window's Cancel button.
- **Results.** `eludite.test.results` (read): `run?` (default the last), `outcome?` filter, `ids?`, `max_output_chars` (default 4,000), cursor. The window's output pane shows the selected test's output and failure.
- **Debugging a test.** `eludite.test.debug` (execute): `ids` (one or more of one project) or `filter`, `wait_ms`, brief 0025's budget parameters. Builds first (the build gate), then starts a brief 0028 session: for MTP the test application with `--filter`/`--treenode-filter` for the ids under the adapter (netcoredbg on .NET, `eludite-dbg-mono` for net4x off Windows); for VSTest the runner's process start info from `GetTestRunnerProcessStartInfoForRunAll` under the adapter (the host passes the start info to the shell); for Rust brief 0029's `test: true` with `--exact` filters. The session breaks at the first line of the first test in the set (a temporary breakpoint from the discovered source and line) and answers the stop summary; Debug All Tests and the window's Debug button do the same. Test results of a debugged run still flow (MTP server mode is used for the debugged application too, with `--server` and the adapter attached after the application starts, or the application is launched under the adapter with `--client-port` and the host connects; say which).
- **Out of process, never blocking.** The host runs test applications and `vstest.console` as child processes; the shell runs cargo as brief 0019 does; the UI thread never waits; every message carries the solution generation; a host restart replays the running run's status (`eludite/test/status`).
- **Visual Studio names.** Test Explorer, Run All Tests (Ctrl+R, A), Debug All Tests (Ctrl+R, Ctrl+A), Run (Ctrl+R, T), Debug (Ctrl+R, Ctrl+T), Run Failed Tests, Repeat Last Run (Ctrl+R, L), the outcome glyphs (green check, red cross, blue skip, grey not run), grouping by project then class, the search box with `FullName:`, `Outcome:`, `Trait:` filters, the summary line.
- Commit messages: one plain, direct, active-voice line each; no body, no trailers.

## Proving test

- `dotnet/tests`: against the four corpus test projects built in a temp folder, MTP discovery and run with the expected outcomes, output and durations; VSTest discovery and run; cancel mid-run; the model mapping; the host RPC round trips with the generation rule and the status replay; `TestProjectInspector` on the corpus projects.
- `crates/eludite` headless tests (fake host from brief 0007's harness extended with `eludite/test/*`, and the real cargo path on the corpus Cargo package): the window opens with the tree, Run All streams results into rows and the Error List, Run Failed and Repeat Last Run, the filter box, Cancel, the agent runs `discover`, `run` with `wait_ms` and reads `results` with the same data the window shows; `test.debug` starts a session that breaks at the test's first line (fake adapter, and the real `eludite-dbg-mono` on an MTP xunit.v3 project built for `net472` if xunit.v3 runs on Mono; otherwise netcoredbg-gated and the Rust path with lldb-dap, which runs here); cargo tests listed and run with the libtest parsing (including a failing test's message and an ignored test).
- Real host: a test in `crates/lsp/tests/real_host.rs` style that discovers and runs the MTP corpus project through the real `eludite-host` (skips when the host is not built).
- The Xvfb run (`crates/eludite/tools/tests-linux.sh`): screenshots of the Test Explorer with results and a debugged test at its breakpoint, recorded in the report.

## Budget

- Discovery of a 100-test MTP project (corpus project extended with generated tests in the test) under 3 s warm after the build; the tree rendered in under 50 ms.
- Run All of the corpus (four .NET projects plus the Cargo package) to the summary under 20 s warm.
- First result row in the window under 100 ms after the runner reports it.
- Debug Test to the first stop under 3 s warm (Rust with lldb-dap, and .NET where an adapter runs).
- No new Rust dependency; .NET: `Microsoft.TestPlatform.TranslationLayer` (MIT) is allowed if the hand-written protocol proves worse; record the SPDX id.

## Exit criterion

1. `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` green with the cargo-test path and the lldb-dap debug-test path running here; `dotnet build` zero warnings and `dotnet test` green with the MTP and VSTest tests running against the built corpus; `corpus/tests/build.sh` builds.
2. The report records the budgets, the MTP and VSTest protocol findings (versions, messages used, quirks), what xunit.v3, xunit 2, MSTest and NUnit each needed, the Rust parsing limits, and what proposal 0001's proving scenario needs to use `eludite.test.debug`.
3. `CLAUDE.md`, `README.md`, `corpus/README.md` and the briefs index match the repository.
