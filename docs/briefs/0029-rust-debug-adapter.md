## Goal

F5 on a Cargo package debugs its binary under LLDB through the Debug Adapter Protocol, with every debugger window, key and `eludite.debug.*` command of briefs 0018, 0025 and 0026 working unchanged, so Eludite debugs Eludite. The adapter is `lldb-dap` from LLVM (Apache-2.0 with LLVM exception), located on the machine (distribution packages install it as `lldb-dap`, `lldb-dap-18` or `/usr/lib/llvm-*/bin/lldb-dap`; Xcode's toolchain on macOS; LLVM's Windows installer), with CodeLLDB (MIT) as an alternative the same code path accepts; neither is vendored. Rust values read as Rust (`String`, `Vec<T>`, `Option<T>`, enums, slices) through the Rust toolchain's own LLDB formatters (`lib/rustlib/etc/lldb_lookup.py`, `lldb_providers.py`, shipped with every rustup toolchain and `rust-lldb`), loaded through `lldb-dap`'s `initCommands`. The launch configuration comes from the Cargo model: the package's binary target, built by brief 0019's build path, whose JSON artifact message names the executable. Set as Startup Project works on Cargo packages (brief 0020 disabled it until this brief).

## Contract

- **Selection.** A startup project that is a Cargo package (brief 0019's `kind: cargo`) debugs under lldb-dap on every platform; the `.NET` rules of brief 0022 are unchanged. `session.runtime` is `native`, `session.adapter` reads `lldb-dap 18.1.3 (stdio)` (the version from `lldb-dap --version`, or the `initialize` answer when it has none, read once on the launch thread). Without lldb-dap, F5 says where it looked and names the package to install for this platform (from `tools/lldb-dap/README.md`).
- **Launch configuration.** The package's binary target (its only `bin`, or `target` names one, else refused listing them), the executable from the artifact message of the build that F5 ran (brief 0019's `cargo build --message-format=json...` gives `executable` for binaries and test executables), or `target/debug/<name>` when `build` is false; `test: true` builds and debugs the package's test executable (`cargo test --no-run --message-format=json -p <package>`) with `args` as the test filter and `--nocapture` as `cargo test` passes them; `cwd` is the workspace root (what `cargo run` uses); `args` and `env` from `[package.metadata.eludite.run]` in `Cargo.toml` when present (`args` a list, `env` a table), else none. `Release` configuration (brief 0019's build setting) maps to `--release` and `target/release/`.
- **Formatters.** `initCommands` loads the Rust formatters from `<sysroot>/lib/rustlib/etc` of the toolchain cargo used (`rustc --print sysroot`, honoring `rust-toolchain.toml`), exactly the commands `rust-lldb` runs, when `debugger.rustFormatters` is on (default) and the files exist; otherwise none, and the report says what a `String` then looks like. Values in Locals read `"hello"` for a `String`, `size=3` with children for a `Vec<i32>`, `Some(5)` for an `Option<i32>`, an enum by its variant.
- **Breakpoints, stepping, stack, locals, evaluate, exceptions.** Through the adapter: conditional and hit-count breakpoints (lldb-dap advertises `supportsHitConditionalBreakpoints`), function breakpoints, log points (`supportsLogPoints`), `setVariable`, `exceptionInfo`, `gotoTargets` (lldb-dap 18 has `supportsGotoTargetsRequest`? record what it answers; Set Next Statement through brief 0026 works when it does), `pause`, `restart` (`supportsRestartRequest`), `disconnect` with `terminateDebuggee`. Exception filters: lldb-dap's `cpp_throw`, `cpp_catch`, and for Rust the panic hook breakpoint: Exception Settings gains a "Rust panics" row that sets a function breakpoint on `rust_panic` (what `rust-lldb` users do), default on, persisted. External code: frames in `std` and in the toolchain's sources are `external: true` unless the source exists on this machine (the `rust-src` component), in which case they open.
- **Cargo test debugging.** `start` with `test: true` and `args: ["my_test"]` breaks in `my_test`; the Test Explorer (a later brief) will call the same.
- **Set as Startup Project** on a Cargo package persists as for .NET projects (the same `startup_project` field, a path to the package's `Cargo.toml`); the Workspace window shows it bold; F5 builds (through the Cargo build path, the build gate of brief 0020) then launches.
- The UI thread never waits: discovery, `rustc --print sysroot`, `lldb-dap --version` and the launch run on the launch thread.
- Commit messages: one plain, direct, active-voice line each; no body, no trailers.

## Proving test

- `crates/dap`: discovery order with temp directories (the versioned names, the llvm path, the setting); the launch arguments including `initCommands` from a fake sysroot; the executable from a recorded artifact message; `[package.metadata.eludite.run]` parsing; the test-executable command line.
- `crates/dap/tests/lldb.rs` (skips with a message when lldb-dap or cargo is missing): builds a small Cargo program (a `String`, a `Vec<i32>`, an `Option<i32>`, an enum, a function with locals, a `panic!` behind an argument, a test function) in a temp dir, launches it under the real lldb-dap through `eludite-dap` with the formatters, and checks: the breakpoint hit, the stack with the caller, locals with Rust formatting (`"hello"`, `size=3`, `Some(5)`, the variant), `evaluate` of a local and of `v.len()`? (record what lldb-dap's expression evaluator does with Rust: it is C++-flavored; `v.len()` fails, `v` works), `next`, `stepIn` into a user function and over `std`, `setVariable` on an `i32`, a log point line, the panic breaking at `rust_panic` with the stack through `main`, `pause`, `disconnect`; the test executable launched with a filter breaks in the test. Timings for the budgets.
- `crates/eludite` headless tests (fake adapter): a folder with a Cargo workspace whose startup project is a package gets an `lldb` plan (adapter id, `program` under `target/debug`, `initCommands`, `cwd`), `runtime` `native` in the state, F5 builds through the Cargo path first and launches on success (and does not on failure), Set as Startup Project on the package persists and shows bold, the Rust panics row in Exception Settings sends a function breakpoint, Ctrl+F5 runs the executable; the settings reach the search.
- No display: headless; the report says so. Dogfooding: the report shows `cargo test -p eludite-dap --test lldb` passing against this repository's own `eludite-cdp-generator` binary or another small member as the debuggee, if its build fits the test's time budget; otherwise the temp program.

## Budget

- Launch to the first `stopped` at a breakpoint in the temp program under 3 s warm (report cold too), measured by the real-adapter test.
- `next` round trip under 150 ms p95 over 50 steps.
- Locals of a frame with a `Vec` of 10,000 elements paged by brief 0025's `variables` in under 100 ms per page.
- Cold start of Eludite unchanged; no new dependency.

## Exit criterion

1. `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` green with the lldb-dap test running on this machine (lldb-dap-18 is installed); `dotnet build` and `dotnet test` unchanged and green.
2. The report records the budget numbers, lldb-dap 18's capabilities and gaps (as brief 0018's section 5), what the Rust formatters do and do not format, the evaluator's limits, and what the Test Explorer brief needs for `cargo test` debugging.
3. `CLAUDE.md`, `README.md`, the briefs index and `tools/lldb-dap/README.md` match the repository.

## Out of scope

- Debugging C or C++ projects (no project model for them yet), remote LLDB (`lldb-server`), core dumps, the Memory and Disassembly windows.
- The Test Explorer and `cargo test` listing (a later brief).
- Windows and macOS runs.
