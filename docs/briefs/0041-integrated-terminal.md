## Goal

View > Terminal (Ctrl+`) opens Visual Studio's Terminal tool window at the bottom beside Output and Error List: a tab per shell with the profile's name (Developer PowerShell, PowerShell, Command Prompt on Windows; the user's `$SHELL`, bash, zsh, fish, sh elsewhere), a profile dropdown with New Terminal and Split, a scrollback with selection, copy and paste, find (Ctrl+F in the window), links to files and `path(line,col)` references that open in the editor, colors from the theme, and the Visual Studio defaults for the font and bell. A real PTY runs the shell with the workspace's root as the working directory and the `dotnet`, Cargo and tool paths Eludite located added to `PATH` (the Developer PowerShell behavior: `dotnet --version` in the terminal is the SDK Eludite builds with); the terminal emulator is `alacritty_terminal` (Apache-2.0, from crates.io, never vendored and never Zed's view), drawn by our own GPUI view in `crates/terminal`. Agents use the same terminal through `eludite.terminal.*`: open a terminal, send input, read the screen or the output since a mark, wait for the prompt or a pattern, resize, kill, with the policy's `terminal` object deciding whether agents may run commands; what the agent types shows in the window in real time and the person can type into the same terminal.

## Contract

- **The PTY and the emulator.** A terminal is a PTY running the profile's shell with the workspace root (or the given `cwd`) and the tool paths; output is parsed by `alacritty_terminal` on its own thread and drawn on the next frame; input, resize and the scrollback cap work as in any terminal; the shell's exit shows "[Process exited with code N]" and the tab offers Restart.
- **Both drivers.** `send` writes to the same PTY the person types into; the tab shows "Agent <name> is typing" while a `send` or `wait` is in flight; the person's keystroke during an agent's `wait` ends it with `interrupted_by: "user"` (as briefs 0027 and 0032 do) and the agent's next `send` is refused until it `read`s again; `read` and `wait` are always allowed, `send` and `open` follow `terminal.run` (`prompt` by default: the first `send` of a session asks, as a dangerous action does, and the answer holds for the session when the person says "Allow for this session").
- **Shell integration.** With integration on and a supporting shell, `wait prompt` returns at the next prompt with the last command's exit code; `read since` returns the output of the commands since the mark; without it the heuristic applies and the output says `integration: false`. Integration never changes the user's dotfiles: the script is sourced through the shell's startup variables (`ZDOTDIR`, `--rcfile`, `-NoExit -Command`, fish's `--init-command`) and chains to the user's own files.
- **Links.** Paths relative to the terminal's `cwd` and absolute ones, with `(line,col)`, `:line:col` and `:line` suffixes, URLs; Ctrl+click opens the editor at the position (plain click selects); `path` links to directories open the Workspace at the folder.
- **Keys and clipboard.** Visual Studio's: Ctrl+C with a selection copies, else interrupts; Ctrl+V pastes (bracketed paste when the application asked for it); Ctrl+Shift+C and Ctrl+Shift+V always copy and paste; Shift+Insert pastes; the reserved chords listed in the report go to the shell window, everything else to the terminal.
- **Budgets and invariants.** The UI thread never waits on the PTY; a terminal's thread coalesces output into at most one grid update per frame; 10,000 lines of scrollback per terminal at most (setting); `cat` of a 100 MB file keeps the frame under 8 ms p99 with the grid update deferred; no network; nothing starts at startup (the window restores closed-tab names only, no shells, unless `terminal.restoreOnOpen` which this brief does not add).
- Commit messages: one plain, direct, active-voice line each; no body, no trailers.

## Proving test

- `crates/terminal`: a PTY runs `sh` scripts: `echo` round trip, a 50,000-line output capped at the scrollback, resize changes `COLUMNS` as seen by `tput cols`, the exit code, selection text across wrapped lines, the link detector's forms, OSC 133 marks give per-command exit codes under bash with the integration script, the heuristic without it, the environment has the tool paths once, SIGINT reaches a `sleep` on Ctrl+C, bracketed paste, the bell event, a `find` in the scrollback.
- `crates/eludite` headless tests (a real `sh` under the shell's fake-free terminal; `sh` exists on every CI runner, PowerShell on Windows): Ctrl+` opens the window with a terminal in the workspace root, New Terminal adds a tab with the profile's name, Split shows two, Kill closes, the exit message and Restart, typing reaches the shell and the output renders, an agent's `open`, `send`, `wait prompt` and `read since` round-trip `echo` with the marker shown on the tab during the call, the person's keystroke interrupts the agent's `wait` and the next `send` is refused, `terminal.run` `deny` refuses and `prompt` asks once per session, Ctrl+click on `src/lib.rs:3:1` printed by the shell opens the editor at line 3, Open in Terminal from the Workspace uses the folder, the reserved chords reach the shell window (Ctrl+Shift+B builds while the terminal has focus), the layout migration puts the window in the bottom group, closing the workspace ends the shells and a running child asks.
- The Xvfb run's screenshots in the report, with `dotnet --version` printing the pinned SDK from the terminal.

## Budget

- Keystroke to the echoed character painted: under 16 ms p95 (Xvfb; measured by the view's frame counter).
- `cat` of a 100 MB file: frame p99 under 8 ms with `assert_budget`; the output finishes within 2 times the plain terminal's time.
- Memory: 10,000 lines of scrollback under 20 MB per terminal.
- One new dependency: `alacritty_terminal` (Apache-2.0, SPDX: Apache-2.0, crates.io), named in the PR; its own dependencies' licenses listed in the report. No other new dependency.

## Exit criterion

1. `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` green with the PTY tests running on Linux; the Windows CI job builds (ConPTY through the same crate) and runs the tests that do not need `sh`.
2. The report records the budget numbers, the key routing table, the shell integration matrix (bash, zsh, fish, sh, PowerShell) and what Developer PowerShell on Windows needs from a located Build Tools.
3. `CLAUDE.md`'s row for `crates/terminal`, `README.md`, the layout schema note in the docking row, the briefs index and the MCP resource list match the repository.
