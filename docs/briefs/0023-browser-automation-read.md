# Brief 0023: Browser automation over CDP against an external Chrome: tabs, navigation and reading the page

Status: in progress
Phase: 2 (proposal 0002, brief A, first half)
Plan reference: PLAN.md sections 2 (principles 1, 2, 3, 5, 6), 3 (D2, D3), 4.9, 5.1, 5.3, 5.4, 5.8, 9, 10 (Phase 2), 12; proposal 0002 sections 2 (the last row: an external Chrome as the first proving step), 4.1, 4.2, 4.3 (`evaluate` only), 5, 6, 7, 8 (A)
Related ADRs: ADR-0002, ADR-0003, ADR-0008
Depends on: brief 0016 (the MCP endpoint), brief 0020 (settings). Runs in parallel with brief 0022 and must not touch its files.

## Goal

An agent (and, through the same commands, a test) drives a real Chromium through Eludite: `eludite.browser.tabs`, `tab_open`, `tab_close`, `tab_select`, `navigate`, `resize`, `screenshot`, `read_page`, `find`, `page_text`, `console`, `network`, `wait` and `evaluate` exist on the command bus with schemas in `protocol/schemas/`, are exposed as MCP tools (a screenshot arrives as MCP image content), are audited, and work against an external Chrome or Chromium that Eludite launches with a per-workspace profile, over the Chrome DevTools Protocol (CDP) on a websocket. The CDP domain types are generated from the pinned protocol JSON into `protocol/`, never hand-written. The engine sits behind one trait so brief B's embedded CEF engine and a later Servo are implementations, not redesigns. This is the first half of proposal 0002's brief A; acting on the page (`input`, `form_input`, `upload`, `storage`, `network_body`), the `browser` policy object with the origin rule, the transcript thumbnails and the fake-agent form proof are brief 0024.

Established before this brief (2026-10-02, this machine): Playwright's Chromium 141.0.7390.37 at `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` started with `--headless=new --remote-debugging-port=9333 --user-data-dir=... --no-first-run` (and `--no-sandbox`, because this container runs as root) answers `http://127.0.0.1:9333/json/version` with `webSocketDebuggerUrl` and `/json/list` with the page target. The npm package `devtools-protocol` 0.0.1709723 (BSD-3-Clause, `https://registry.npmjs.org/devtools-protocol/-/devtools-protocol-0.0.1709723.tgz`) carries `json/browser_protocol.json` (1.4 MB, 53 domains) and `json/js_protocol.json` (180 KB) for a current Chromium; Chrome for Testing's stable channel is 154.0.8037.92 (`https://storage.googleapis.com/chrome-for-testing-public/154.0.8037.92/<platform>/chrome-<platform>.zip`, platforms `linux64`, `win64`, `mac-arm64`, `mac-x64`). Both hosts are reachable from CI.

## Contract

### Protocol artifacts

- `protocol/cdp/browser_protocol.json` and `js_protocol.json` are byte-identical to the pinned package's; `fetch.sh` re-fetches and verifies them. The generator reads both and emits Rust for these domains and every domain they reference transitively: `Target`, `Page`, `DOM`, `Accessibility`, `Runtime`, `Log`, `Network`, `Input`, `Emulation`, `Browser`, `Security`. For each domain: one `serde` struct per type (`object`), a newtype or alias per string, integer and number type, a string enum per `enum` (unknown values decode as an `Other(String)` variant, since Chrome adds values), a `<Command>Params` and `<Command>Returns` struct per command with `const METHOD: &str`, and one struct per event with `const NAME`. Optional members are `Option<T>` with `skip_serializing_if`; `any` is `serde_json::Value`; `binary` is `String` (base64); recursive types are boxed; identifiers that are Rust keywords are renamed with `#[serde(rename)]`; `experimental` and `deprecated` members are kept and documented as such. Generated code is `rustfmt`-clean and `clippy`-clean under `-D warnings` (an `#![allow(...)]` list at the top of each generated file is acceptable for lints generated code cannot avoid, such as `clippy::large_enum_variant`). A generator test regenerates into a temporary directory and compares with the checked-in files.
- CDP messages (`id`, `method`, `params`, `sessionId`, `result`, `error`) are typed in `crates/browser`, not generated (the JSON does not describe them).

### The engine

- `crates/browser` exposes `Engine` (a trait: open and close tabs, attach a tab, send a CDP command on a tab's session, subscribe to its events, screenshot pixels) with `ExternalChrome` as the implementation: it launches `chrome` with `--remote-debugging-port=0 --user-data-dir=<workspace>/.eludite/browser/profile --no-first-run --no-default-browser-check --disable-background-networking --disable-sync --disable-default-apps` plus `--headless=new` when `browser.headless` is on, `--window-size` from `browser.viewport`, and `--no-sandbox` only when the environment variable `ELUDITE_CHROME_NO_SANDBOX=1` is set (tests set it when they run as root; the shell never sets it). It reads `DevTools listening on ws://...` from Chrome's stderr (10 s timeout), connects to the browser websocket, uses `Target.setDiscoverTargets`, `Target.attachToTarget` with `flatten: true` for a session per page, and `Target.createTarget` and `closeTarget` for tabs. The profile directory is created with the workspace's `.eludite/` and added to its `.gitignore` entry the agents' policy file uses, if one exists; the browser process is killed with the workspace and on shell exit.
- Chrome discovery, in order: the setting `browser.chromePath` (`ELUDITE_CHROME`), then `~/.cache/eludite/chrome/<pinned version>/<platform>/chrome` (what `tools/chrome/fetch.sh` installs), then on `PATH` `google-chrome`, `google-chrome-stable`, `chromium`, `chromium-browser`, `chrome`, then the platform's usual install locations (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, `%ProgramFiles%\Google\Chrome\Application\chrome.exe`, and the same under `%ProgramFiles(x86)%` and `%LocalAppData%`). The error for none found names every place and `tools/chrome/fetch.sh`.
- The websocket client is `tungstenite` (MIT OR Apache-2.0) over `std::net::TcpStream`, no TLS, no async runtime (as `crates/mcp` and `crates/dap` do). One reader thread per connection delivers responses to waiting requests and events to subscribers; a request has a timeout (default 10 s) and never blocks a caller that did not ask to wait. A closed connection fails every pending request and marks the engine gone; the next command relaunches the browser.
- Each tab keeps a `page_generation` that increments on `Page.frameNavigated` of the main frame and on `DOM.documentUpdated`; refs (`ref` strings `e1`, `e2`, ... mapped to CDP backend node ids) are issued by `read_page` and `find`, carry the generation they were issued at, and are refused with the message "stale ref: the page changed (generation N, ref from M); call read_page again" when used after it changed. Console messages (`Runtime.consoleAPICalled`, `Runtime.exceptionThrown`, `Log.entryAdded`) and network requests (`Network.requestWillBeSent`, `responseReceived`, `loadingFinished`, `loadingFailed`) go into rings of 2,000 and 5,000 entries per tab with monotonically increasing cursors; `dropped` counts entries the ring overwrote since the cursor.

### The commands

All ids `eludite.browser.*`, `agent_visible: true`, `tab` optional everywhere (default: the active tab), every output carrying `page_generation` where the proposal says so. Classes per proposal 0002 section 4: `tabs`, `screenshot`, `read_page`, `find`, `page_text`, `console`, `network` and `wait` are `read`; `tab_open`, `tab_close`, `tab_select`, `navigate`, `resize` and `evaluate` are `execute` (the origin rule that makes `navigate` `dangerous` off the allowed origins arrives with the policy object in brief 0024; the schema description says so). Each input schema's root `description` is written for a model: when to use the tool, what it costs, what to call next.

- `tabs`: the tabs (id, url, title, active, loading, `page_generation`) and `engine` (`external-chrome`, its version from `Browser.getVersion`) and whether the browser is running; it launches nothing.
- `tab_open` (`url?`): launches the browser if needed, opens a tab, selects it, navigates when a url is given (waiting for `load`). Answers the tab.
- `tab_close` (`tab`), `tab_select` (`tab`).
- `navigate`: `url` or `action` (`back`, `forward`, `reload`), `wait_until` (`load` default, `domcontentloaded`, `network_idle`: no request in flight for 500 ms, `none`), `wait_ms` (default 30,000). Answers the final url, title, HTTP status of the main document, `page_generation`, and the count of console errors during the load. A navigation error (`net::ERR_*`) is a failed command naming it.
- `resize`: `width`, `height`, `device_scale_factor?`, `mobile?`, `user_agent?` through `Emulation.setDeviceMetricsOverride` and `setUserAgentOverride`; answers the viewport in effect.
- `screenshot`: `full_page?`, `clip?` (a ref or `{x, y, width, height}` in CSS pixels), `max_width` (default 1280: the image is captured at the viewport and scaled down with `Page.captureScreenshot`'s `clip.scale` when wider), `format` (`png` default, `jpeg` with `quality`). Output: `image` (base64, with `contentEncoding` `base64` and `contentMediaType` in the schema, and `x-eludite-mcp-content: image`), `width`, `height`, `scale`, `page_generation`.
- `read_page`: `mode` (`accessibility` default: `Accessibility.getFullAXTree`, `dom`: `DOM.getDocument` with `depth: -1`), `filter` (`interactive` default: nodes with a role among button, link, textbox, checkbox, radio, combobox, listbox, option, menuitem, tab, slider, spinbutton, switch, searchbox, or with a name and focusable; `all`), `root?` (a ref), `max_nodes` (default 500). Output: a flat list in document order with `ref`, `role`, `name`, `value?`, `description?`, `state` (checked, disabled, expanded, focused, selected, required, invalid when present), `box` (x, y, width, height from `DOM.getBoxModel`, omitted when the node has none), `depth`; `total`, `truncated`, `page_generation`. Nodes are given refs only here and in `find`.
- `find`: `css?` (`DOM.querySelectorAll`), `text?` (`DOM.performSearch`), `role?` with `name?` (over the accessibility tree), `max` (default 20). Output: refs with role, name and box.
- `page_text`: `root?`, `max_chars` (default 20,000), `cursor?`: the rendered inner text (`Runtime.evaluate` of `innerText` on the root), paged; `next` cursor.
- `console`: `since` (cursor, default 0), `level?` (`error`, `warning`, `info`, `log`, `debug`), `pattern?` (a substring or `/regex/`), `max` (default 100). Output: messages with `level`, `text`, `url`, `line`, `column`, `stack` for errors, `timestamp`, `seq`; `next`, `dropped`.
- `network`: `since`, `url_pattern?`, `status?`, `resource_type?`, `max` (default 100). Output: requests with `request_id`, `method`, `url`, `status`, `resource_type`, `mime_type`, `started_at`, `duration_ms`, `encoded_bytes`, `failed?` with the error text, `initiator` (type and url); `next`.
- `wait`: `for` (`selector` with `css`, `text` with `text`, `navigation`, `network_idle`, `console` with `pattern`, `function` with `expression` returning truthy), `wait_ms` (default 10,000, max 60,000), polled every 100 ms or event-driven where CDP offers the event. Output: `satisfied` (what matched, with the ref for `selector`), `page_generation`, or `timeout: true`.
- `evaluate`: `expression`, `await?` (default true: `awaitPromise`), `return_by_value?` (default true), `max_chars` (default 10,000). Output: `result` (JSON; strings longer than `max_chars` cut with `truncated: true`), `type`, or `exception` with `text` and `stack` as a failed command.

### MCP image content

- `crates/mcp`: when a command's output schema marks a top-level string property with `"x-eludite-mcp-content": "image"`, `tools/call`'s `content` gets `{"type": "image", "data": <the property>, "mimeType": <contentMediaType>}` after the text part, and the text part and `structuredContent` carry the output with that property replaced by the string `"(image content)"`, so the base64 is sent once. `protocol/schemas/mcp-tool.json`'s description records the rule.

### Threads and the person

- The shell runs every browser command on its `browser` worker thread; the UI thread never waits on Chrome (invariant 1). Agents' calls arrive on the MCP thread and block there as other commands do.
- The Output window's `Browser` source shows: the launch (executable, version, endpoint), tabs opened and closed, navigation failures, console errors (as `[tab] url:line: text`), and the browser's exit. There is no Web Browser window yet (brief B); the person's surface is the Output source and the Agents window's transcript rows (generic rendering; thumbnails are brief 0024).
- Audit: every call is an audit entry as every command is; nothing more here.
- Commit messages: one plain, direct, active-voice line each; no body, no trailers.

## Proving test

- `eludite-cdp-generator`: the checked-in `protocol/rust/src/cdp/` equals a fresh generation; the generated crate compiles and round-trips three samples through serde (`Page.captureScreenshot` returns, a `Runtime.consoleAPICalled` event, an `Accessibility.AXNode` with an unknown role).
- `crates/browser` unit tests (no Chrome): CDP message framing and correlation against a fake websocket server in process (`tungstenite` accepts too); the request timeout; refs and generations (a ref from generation 1 refused at 2); the rings' cursors and `dropped`; discovery order with temp directories; the launch command line; the `interactive` filter over a recorded accessibility tree (a JSON fixture captured once from Chrome and checked in).
- `crates/browser/tests/chrome.rs` (skip with a message when no Chrome is found): a std-only HTTP server in the test serves fixtures from `crates/browser/tests/fixtures/` (a form page, a page with 5,000 list items, a page that logs an error and fetches a missing resource, a page whose button rewrites the document). Against a launched headless Chrome: `tabs` before launch says not running; `tab_open` with a url; `navigate` to each fixture with `load` and `network_idle`; `screenshot` (decode the PNG header: dimensions match the viewport scaled to `max_width`); `read_page` interactive lists the form's controls with refs and boxes; `find` by css, text and role+name; `page_text` paging; `console` returns the error with `url:line` and `network` the 404 with its status; `wait` for a selector that appears after a timeout the page sets, and `wait` `function`; `evaluate` returning an object, a string cut at `max_chars`, and an exception as a failed command; the rewrite button bumps `page_generation` and a stale ref is refused; `tab_close`; killing Chrome fails pending requests and the next `tab_open` relaunches it. Timings for the budgets are printed to the test output.
- `crates/mcp`: a command whose output has the image marker produces image content and the replaced text.
- `crates/eludite` headless tests: the commands are registered and agent-visible with their schemas; `eludite.browser.tabs` through the bus answers off the UI thread (a fake `Engine` that blocks 200 ms must not delay a frame); the Output source receives the lifecycle lines; the settings reach the launcher; the browser is closed with the workspace.
- No display: Chrome runs with `--headless=new` here and in CI; the report says so.

## Budget

- `screenshot` round trip at 1280 wide: under 150 ms p95 over 20 calls (proposal 0002 section 7).
- `read_page` on the 5,000-node fixture: under 300 ms p95 over 20 calls, answer under 64 KB with the default `max_nodes`.
- `navigate` to a local fixture with `load`: under 500 ms p95.
- Cold start of Eludite unchanged: `crates/browser` does nothing until the first browser command.
- Shell resident memory with the browser running and idle: plus 20 MB at most (the browser's processes are separate).
