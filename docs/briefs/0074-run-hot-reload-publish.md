## Goal

Running a .NET program from Eludite behaves like Visual Studio and Rider:

1. **The launch target comes from MSBuild evaluation.** F5 and Ctrl+F5 run the program `dotnet run` would run: `TargetPath`, `RunCommand`, `RunArguments`, `RunWorkingDirectory`, `OutputType` and the target framework from evaluating the project in the selected configuration, platform and framework, so `Directory.Build.props`, `UseArtifactsOutput`, `BaseOutputPath`, `AssemblyName` and `RuntimeIdentifier` set anywhere are honored. Today's text-reading guess stays as the fallback when the host is not running.
2. **Console programs run in the integrated terminal.** Ctrl+F5 on a console project runs it in a new Terminal window tab on a real PTY, so stdin, colors, `Console.ReadKey` and prompts without a newline work; when it exits the tab says `<program> (process <pid>) exited with code <n>.` and `Press any key to close this window . . .` like Visual Studio's console. Setting `debug.console`: `integratedTerminal` (default) or `output` (the old Output pane). Web projects keep the Output pane. Under F5 the shell answers DAP's `runInTerminal` reverse request by starting the command in a terminal tab and returning its process id (any adapter that asks: lldb-dap, js-debug); netcoredbg 3.2 never asks (its vscode protocol has no `console` argument and does not forward stdin), and the report says so.
3. **Every launch profile kind is honored or refused clearly.** `Executable` profiles run `executablePath` with `commandLineArgs`, `workingDirectory` and `environmentVariables` (with `$(ProjectDir)`, `$(TargetDir)`, `$(TargetPath)` expanded); `Docker`, `DockerCompose`, `WSL2`/`WSL`, `SdkContainer` and `IISExpress`/`IIS` off Windows are refused with one message naming the profile kind.
4. **Hot Reload through `dotnet watch`.** Debug > Start Without Debugging with Hot Reload (`eludite.debug.run_watch`, Visual Studio's 🔥 button on the Debug toolbar) runs `dotnet watch` for the startup project in a Terminal tab, parses its output into a Hot Reload state shown in the status bar (`Hot Reload: watching`, `applied`, `compilation errors`, `restart needed`, `restarting`, `exited`), answers rude-edit restarts per `hotReload.restartOnRudeEdit` (`prompt`, `always`, `never`), and Alt+F10 (Apply Code Changes) saves all documents so the watcher applies them. Shift+F5 stops it (the process tree).
5. **Publish to a folder.** Publish... on a project's Workspace context menu and Build > Publish Selection open a small dialog in Visual Studio's shape over `Properties/PublishProfiles/*.pubxml` (folder target: configuration, target framework, runtime, deployment mode, single file, ReadyToRun, trimming, target location), saved preserving the file; Publish runs the host's new `publish` build target (`dotnet publish <project> -p:PublishProfile=<name>`), streamed into the Output window's Build pane with Error List rows. `eludite.build.publish` does the same for agents.

## Contract

**`eludite/project/runTarget`** (schema first). Params `project` (absolute, a project of the open solution), optional `configuration`, `platform`, `framework` (default: the solution configuration's mapping, then the project's first target framework). Result: `generation`, `project`, `configuration`, `platform`, `framework` (the target framework evaluated; absent for a legacy project), `targetFrameworks`, `targetFrameworkIdentifier` (`.NETCoreApp`, `.NETFramework`, ...), `outputType`, `targetPath`, `runCommand`, `runArguments`, `runWorkingDirectory` (as `dotnet run` computes them at evaluation: `Microsoft.NET.Sdk.targets` sets them in a property group, the `ComputeRunArguments` target is empty in the SDK), `isWebProject` (`UsingMicrosoftNETSdkWeb`), `exists` (whether `targetPath` is on disk). It runs on the property evaluator's shared collection and lock, cached per generation and key like `eludite/project/properties`.

**The launch.** The launch thread asks the host once (`< 50 ms` warm; the UI thread never waits) and builds the `LaunchConfig` from the answer: `program` = `targetPath` (CoreCLR: the DLL netcoredbg runs; .NET Framework: the `.exe`); Ctrl+F5 runs `runCommand runArguments` in `runWorkingDirectory` unless the profile sets a working directory; `framework kind` from `targetFrameworkIdentifier`. A host that is not running, a failure or a timeout (10 s) falls back to `launch::launch_config_in` as today. A target that does not exist says `<name> is not built: <targetPath> does not exist. Build the project first`.

**Profiles.** `LaunchProfile` gains `executable_path`. `commandName` decides: `Project` (as today), `Executable` (program `executablePath` resolved against the project folder with `$(ProjectDir)`, `$(TargetDir)`, `$(TargetPath)` and environment variables `%VAR%`/`$(VAR)` expanded; args `commandLineArgs`; cwd `workingDirectory`; env), refused: `Docker`, `DockerCompose`, `SdkContainer`, `WSL2`, `WSL`, and `IISExpress`/`IIS` off Windows, with `The launch profile '<name>' runs <kind>, which Eludite does not run yet; choose a Project or Executable profile.` (`<kind>`: `in a Docker container`, `in WSL`, `under IIS Express`). An Executable profile under F5 is debugged when the executable is a .NET program (a `.dll`, or `dotnet` with a DLL argument); otherwise Ctrl+F5 runs it and F5 says it cannot debug a native executable from a .NET profile.

**Console in the terminal.** `run_terminal::wrap(program, args, platform)` builds the command a terminal tab runs: on Unix `sh -c '<script>' sh <program> <args>` where the script runs `"$@"`, then prints `\n<program> (process <pid>) exited with code <n>.\nPress any key to close this window . . .`, reads one key in raw mode and exits with the program's code; on Windows `cmd.exe /d /c` with the same lines and `pause >nul`. `TerminalService::open_program(name, program, args, cwd, env)` opens a tab running it (no profile, no shell integration) and returns its id and pid. The launch thread watches the transcript for the exit line and reports `ProgramExited` with the code. Shift+F5 ends the tab's process tree. A program is a console program when `outputType` is `Exe` and it is not a web project; `WinExe` and web projects use the Output pane; `debug.console: output` keeps the Output pane for everything.

**`runInTerminal`.** The shell's reverse handler answers `runInTerminal` (`args`, `cwd`, `env`, `title`) by opening a terminal tab running `args` directly and answering `{processId}`; a failure refuses with its message. `startDebugging` keeps its handler.

**Hot Reload.** `eludite.debug.run_watch` (input: optional `project`, `profile`; output: `state`, `project`, `terminal`, `command`). It builds `dotnet watch --project <p> [--launch-profile <profile>] [-c <configuration>] [-f <framework>] [--non-interactive]` (`--non-interactive` with `DOTNET_WATCH_RESTART_ON_RUDE_EDIT=true` when `hotReload.restartOnRudeEdit` is `always`) and runs it in a terminal tab. `hot_reload::Watch` is a state machine fed the tab's output lines (the transcript, ANSI stripped): `dotnet watch 🔥 Hot reload enabled` → watching; `File updated` / `File changed` → applying; `changes applied` / `Hot reload succeeded` / `Hot reload of changes succeeded` → applied (with the time); `Unable to apply changes due to compilation errors` / `Build failed` → errors; `Restart is needed` / `Do you want to restart your app?` → restart needed (with `never`, the shell answers `v`; `always` answers `a`; `prompt` leaves the question in the tab, focused); `Restarting` / `Exited` → restarting; the tab's process exiting → exited. The status bar's debug slot shows `🔥 Hot Reload: <state>`. Alt+F10 (Debug > Apply Code Changes) saves all dirty documents; with no watcher running it says `Start with Hot Reload first (Debug > Start Without Debugging with Hot Reload)`. Shift+F5 while watching closes the tab with its process tree. `hotReload.onSave` is not added: `dotnet watch` applies a change when the file is written and has no switch to wait for a trigger, so Alt+F10's save is the explicit trigger.

**Publish.** `publish::PublishProfile` reads and writes a `.pubxml` (`PublishProtocol` `FileSystem`, `Configuration`, `TargetFramework`, `RuntimeIdentifier`, `SelfContained`, `PublishSingleFile`, `PublishReadyToRun`, `PublishTrimmed`, `PublishDir`/`PublishUrl`), editing elements in place and adding missing ones to the first `PropertyGroup`, keeping everything else byte for byte; a new profile is `FolderProfile.pubxml` in Visual Studio's template shape with `PublishDir` `bin\Release\<tfm>\publish\` (Visual Studio's default). The host's `publish` target runs `dotnet publish <project> -p:PublishProfile=<path> -tl:off -nologo -v:m` with `-c` only when the request names a configuration; output and diagnostics stream like a build and the Error List fills. `eludite.build.publish` (input `project`, optional `profile` name or path, `wait`; output `build-result.output.json` with target `publish` and `publishDir`). Publish refuses a solution (a project is required), a legacy project, and a profile whose protocol is not `FileSystem`.

## Proving test

- `cargo test -p eludite-protocol`: `run-target.json` conforms to the Rust mirror; `build-start.json` takes `publish`.
- `cargo test -p eludite-dap launch`: the launch config from an evaluated target (artifacts path, run command, working directory); Executable profiles with macros; Docker, WSL and IIS Express profiles refused with the message.
- `cargo test -p eludite-commands`: `eludite.build.publish`, `eludite.debug.run_watch`, `eludite.debug.apply_code_changes` parse and their specs carry the schemas.
- `cargo test -p eludite run_terminal_tests hot_reload_tests publish_tests`: headless, with the fake host: the evaluation answer drives the launch (a program only at the artifacts path runs); Ctrl+F5 on a console project opens a Terminal tab that reads a typed line and shows the exit lines, and the session ends with the exit code; `debug.console: output` keeps the Output pane; the Docker profile is refused with its message; a fake adapter's `runInTerminal` opens a tab and is answered with its pid; the watch parser's states for SDK 10's real lines (captured here); `eludite.debug.run_watch` runs a scripted fake `dotnet` in a tab and the status bar follows it; publish streams through the fake host with target `publish` and the pubxml round-trips.
- `dotnet test --filter RunTarget|Publish` (real SDK): `TargetPath`, `RunCommand` and `RunWorkingDirectory` of `corpus/run/Artifacts/App` under `artifacts/bin/App/debug/`; the publish target publishes `corpus/run/Echo` to a temp folder and the published program runs.
- Real `dotnet watch` (`cargo test -p eludite --test ... ` gated on the SDK being found): a running corpus console app's printed text changes after an edit, and the parser reaches `applied`.
- netcoredbg (gated on `ELUDITE_NETCOREDBG`): F5 on `corpus/run/Echo` launches and runs to exit; the report records that its stdin is not reachable (no `runInTerminal`).

## Budget

- F5 and Ctrl+F5 add one host round trip for the evaluation: `< 50 ms` warm (cached per generation), measured and reported; the UI thread never waits on it.
- The terminal tab opens in the time `eludite.terminal.open` takes today (one PTY spawn).
- Hot Reload's parser costs nothing measurable per line (string scans on lines already in the transcript).

## Exit criterion

1. `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` green on every crate touched; `dotnet build dotnet/Eludite.slnx` and `dotnet test` on the host tests green.
2. The report records the evaluation's latency, what netcoredbg 3.2 supports for console input and Hot Reload under the debugger, and Integration notes.

## Out of scope

Hot Reload under the debugger (Edit and Continue through netcoredbg's `HotReloadApplyDeltas`, which is not exposed over its vscode protocol); container, WSL, IIS and Azure targets (refused profiles; publish to Azure, FTP, Web Deploy and container registries); a `debug.console: externalTerminal`; attaching netcoredbg to a terminal-hosted program before `Main` (a startup hook that waits for the debugger); MAUI, Blazor WebAssembly's `dotnet watch` browser refresh beyond what `dotnet watch` does itself; ClickOnce; the Publish summary page's history.
