# corpus/

Real inputs with their expected outputs, used as golden tests (PLAN.md section 11, "Verification over trust").

Each entry states its origin, its license, which subsystems use it, and the expected outputs checked in beside it.

| Entry | What it is | Used by | Expected outputs |
|---|---|---|---|
| [`legacy/`](legacy/) | Real-world legacy .NET Framework, WebForms and WCF solutions, cloned at pinned commits by `fetch.sh` from `manifest.json` (not checked in) | Brief 0003's legacy project-load spike (`tools/legacy-load`) | In `manifest.json` and brief 0003's report |
| [`debugging/`](debugging/) | Three seeded-bug C# console programs (`OffByOne`, `MissingCase`, `NullField`), `net10.0;net472`, MIT, built by `build.sh` / `build.ps1` | Brief 0030's agent debugging proving scenario: the scripted fake agent's headless tests (`crates/eludite/src/shell/agents/tests.rs`) under netcoredbg or `eludite-dbg-mono`, and the recorded Claude Code run (`crates/eludite/tools/debug-agent-linux.sh`) | The faulting statement, its line and the locals that reveal it, in `debugging/README.md` |
| [`tests/`](tests/) | The Test Explorer corpus: one small test project per protocol and framework (xunit.v3 and MSTest on Microsoft.Testing.Platform, xunit 2 and NUnit on VSTest) and a Cargo package, each with passing, failing, skipped and output-writing tests, MIT, built by `build.sh` / `build.ps1` | Brief 0035: the bridge's and host's tests (`dotnet/tests`), `crates/lsp/tests/real_host.rs`, the shell's Test Explorer tests and the Xvfb run (`crates/eludite/tools/tests-linux.sh`) | Per project in `tests/README.md` |
| [`dap/`](dap/) | Recorded DAP sessions of the real debug adapters (`eludite-dbg-mono` under Mono, lldb-dap, vscode-js-debug with one file per connection; netcoredbg to come from CI), one per scenario, scrubbed of machine paths and process ids, MIT, made only by the recorder (`tools/dap-corpus/record.sh`) | Brief 0033's conformance tests (`crates/eludite/src/shell/debug/conformance_tests.rs`), which replay each recording through the headless shell on every platform; CI's Linux job re-records Mono and lldb-dap and fails on drift | Per step, the debug state, the agent's answer and the debug windows' rows, in `<scenario>.golden.json` beside each recording |
| [`web/minimal-api/`](web/minimal-api/) | A minimal ASP.NET Core project (`Microsoft.NET.Sdk.Web`, `net10.0`): a page with a form posting back to itself and a `/api/time` JSON endpoint, Visual Studio's `http` and `https` launch profiles with `launchBrowser`, MIT, built by `build.sh`; brief 0038 adds `wwwroot/app.ts` compiled once with `tsc` to `app.js` and `app.js.map` (committed: no toolchain at test time) and an Add button whose handler has a bug | Brief 0037's launch integration: the shell's Ctrl+F5 test with the real `dotnet` and the embedded engine (and its netcoredbg twin) in `crates/eludite/src/shell/debug/tests.rs`, and the Xvfb run (`crates/eludite/tools/web-launch-linux.sh`); brief 0038's JavaScript debugging: the fake and real js-debug tests, the js-debug conformance scenarios' page and the Xvfb run (`crates/eludite/tools/js-debug-linux.sh`) | The page, the form's post and the JSON, and Kestrel's listening line; the breakpoint lines in `app.ts` and their `app.js` lines; in `web/minimal-api/README.md` |
| [`web/vite-counter/`](web/vite-counter/) | A Vite TypeScript counter (MIT) with a committed `package-lock.json` (Vite 8.3.2 and its packages: MIT, Apache-2.0, ISC, BSD-3-Clause, MPL-2.0); `node_modules/` is never committed | Brief 0038's real test: `npm ci`, the Vite dev server, a breakpoint in `src/counter.ts` stopping through the dev server's source maps (`crates/eludite/src/shell/debug/tests.rs`) | The breakpoint line and what it shows, in `web/vite-counter/README.md` |
